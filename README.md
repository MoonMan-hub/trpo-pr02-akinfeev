# Практическая работа №2

## CSS, адаптивная вёрстка и SCSS. Организация стилей

## Описание

Адаптивный каталог «Учебный маркет» на HTML и SCSS. На странице:

- шапка с навигацией;
- панель фильтров слева (поиск, категория, диапазон цены, сортировка);
- сетка из 18 карточек товаров;
- информационный блок «О каталоге»;
- подвал.

На экранах уже 900 px панель фильтров переносится над карточками.

## Технологии

- HTML5 (семантические теги `header`, `nav`, `main`, `section`, `aside`, `article`, `form`, `fieldset`, `figure`, `footer`)
- CSS Grid и Flexbox
- SCSS (переменные, вложенность, mixin, функция, partial-файлы)
- Dart Sass (компилятор, ставится через npm)
- Git

## Как используется dataset

- `data/catalog.csv` — из него взяты все 18 карточек (название, категория, цена, рейтинг). Поле `id` используется в `id="product-N"`. Категория определяет картинку и метку (badge).
- `data/theme.json` — значения `accent`, `surface`, `background`, `text`, `radius`, `space` перенесены в `scss/_variables.scss`.
- `images/product-01..03.svg` — картинки категорий: в карточках и в блоке «О каталоге».

## Запуск

Требования: Node.js и npm.

```bash
git clone <ссылка на репозиторий>
cd trpo-pr02-market
npm install
```

Разовая сборка SCSS в CSS:

```bash
npm run sass
```

Режим наблюдения (пересборка при каждом сохранении SCSS):

```bash
npm run watch
```

После сборки откройте `index.html` в браузере. Готовый `css/styles.css` уже лежит в репозитории, поэтому страница откроется и без сборки.

## Сценарий проверки

1. Выполнить `npm install` и `npm run sass` — ошибок быть не должно.
2. Открыть `index.html`, в консоли DevTools ошибок нет.
3. В DevTools → Responsive Mode проверить ширины 375, 768 и 1440 px.
4. Горизонтальной прокрутки быть не должно.
5. Ввести в поле «От» отрицательное число — рамка поля станет красной (состояние `:invalid`).
6. Изменить `$color-accent` в `scss/_variables.scss`, выполнить `npm run sass` — цвет кнопок, меток и рамок при наведении изменится везде.

## Адаптивность

| Ширина | Раскладка | Карточки |
|--------|-----------|----------|
| больше 900 px | панель слева (260 px), карточки справа | 3 колонки |
| до 900 px (breakpoint 1) | панель над карточками, поля в 2 колонки | 2 колонки |
| до 560 px (breakpoint 2) | навигация под логотипом, поля в 1 колонку | 1 колонка, компактная карточка (картинка слева) |

## Что изменилось по шагам

- **Шаг 8 (вложенность).** Стили компонентов записаны через `&__элемент` (например, `.product { &__name {} }`). Глубина вложенности не больше трёх уровней.
- **Шаг 9 (mixin).** Добавлены `container` (адаптивный контейнер) и `focus-ring` (состояние фокуса). Они вынесены в `_mixins.scss`.
- **Шаг 12 (сетка карточек).** Карточки размещены через `display: grid` и `repeat(3, 1fr)`, на меньших экранах число колонок уменьшается.
- **Шаг 13 (breakpoints).** Два breakpoint'а: 900 px (перестройка основной раскладки) и 560 px (плотность карточек и навигация).

## SCSS-переменная и CSS custom property

SCSS-переменная (`$color-accent`) существует только при компиляции: Sass подставляет в `css/styles.css` готовое значение (`#315efb`), и в браузере переменной уже нет. CSS custom property (`--color-accent`) остаётся в браузере и может меняться во время работы страницы, например через JavaScript или медиазапрос. В этой работе нужна именно сборка стилей, поэтому использованы SCSS-переменные.

## Зачем нужны partial-файлы

Файлы с подчёркиванием (`_variables.scss`, `_base.scss` и др.) — partials. Они не компилируются в отдельные CSS-файлы, а подключаются в `styles.scss` через `@use`. Так стили делятся по назначению (переменные, база, раскладка, компоненты), и нужное правило проще найти.

## Где применены mixin и функция

- Mixin `container` (`_mixins.scss`) используется в `_layout.scss` для класса `.container`.
- Mixin `focus-ring` (`_mixins.scss`) используется в `_base.scss` для `:focus-visible` у ссылок, кнопок и полей.
- Функция `space($n)` (`_functions.scss`) возвращает `$n * $space`. Например, `space(2)` — это `32px`. Используется почти во всех partial-файлах для отступов.
